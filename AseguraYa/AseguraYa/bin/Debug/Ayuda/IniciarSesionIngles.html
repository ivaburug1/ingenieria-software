🔐 Help - Log In

1. General Description

This form allows registered users to access the AseguraYa system by entering their ID number (DNI) and password. Security mechanisms are applied to validate credentials, manage failed attempts, and automatically block users after three consecutive errors.

2. Main Objectives

  • Allow access only to valid and active users.
  • Apply format and security validations (SHA256 for passwords).
  • Automatically block users after multiple failed attempts.
  • Record all access events in the system logbook.
  • Start the session with the user's preferred language.

3. Form Operation

  1. The user enters their ID (DNI) and password.
  2. The system verifies that both fields are filled and that the ID is numeric.
  3. The user is searched in the database.
  4. If found, the SHA256 hash of the entered password is calculated and compared to the stored one.
  5. If they match:
    • The session starts and a Singleton instance of the active user is created.
    • Their permissions, language, and profile are loaded.
    • Access events are logged in the system’s event log.
  6. If they do not match:
    • The attempt counter increases.
    • After the third failed attempt, the user is automatically blocked.

4. Validations

  • ID (DNI): must be numeric (validated using a regular expression).
  • Password: cannot be empty.
  • Both fields must be completed before logging in.

5. System Messages

✅ Session started successfully: the user accesses the system without errors.
⚠️ Incorrect user or password: displays the number of remaining attempts.
⚠️ User blocked: after 3 failed attempts, access is locked.
⚠️ User deactivated: the account exists but is administratively inactive.
⚠️ Missing data: one or more fields are empty.
⚠️ Unexpected error: a generic message is displayed with the captured exception.

6. Special Cases

  • If the system detects that the database did not pass integrity verification (DVH/DVV), login is not allowed.
  • Users with the General Administrator permission access the system repair module directly.
  • If the user is required to change their password, the form _686DPfrmChangePassword opens automatically.

7. Common Errors

  • Invalid DNI format → the field contains letters or non-numeric characters.
  • NullReferenceException → may occur if the language or startup dependencies are not properly loaded.
  • UserBlocked → attempting to log in with an already blocked account.
  • DBError → internal error while connecting or retrieving profile data.

8. Usage Tips

  • Ensure the user’s language is correctly configured to avoid untranslated messages.
  • Never share personal credentials.
  • If the account becomes blocked, contact the General Administrator for reactivation.
